# Автотесты

Тесты API работают на встроенном раннере Node (`node --test`) — никаких новых зависимостей. Запуск:

```bash
npm test                 # из корня проекта: собирает пакеты, компилирует и запускает все тесты
npm test -- orders       # только файлы, в пути которых есть «orders»
```

## Два вида тестов

| Файлы | Что проверяют | Нужна БД |
|---|---|---|
| `*.spec.ts` | Чистая логика: расчёт скидки и проверка промокода, срок автоотмены, маска имени автора отзыва, распознавание ссылок хранилища | нет |
| `*.int.spec.ts` | Сервисы на настоящей PostgreSQL: оформление заказа и резервирование остатков, отмена и восстановление заказа, автоотмена неоплаченных, синхронизация платежа ЮKassa (заглушка), отзывы и рейтинг; в том числе **гонки** (параллельные заказы на последнюю единицу, лимит промокода, одновременные отмены) | да |

Без тестовой БД модульные тесты выполняются, а тесты с БД пропускаются.

## Тестовая БД (один раз)

Тесты **очищают все таблицы**, поэтому используется отдельная база. Защита: имя базы обязано содержать `test`, иначе тесты не стартуют; без `TEST_DATABASE_URL` приложение к рабочей БД в тестах вообще не подключается.

1. Создайте базу рядом с рабочей (контейнер из `docker-compose.yml`):
   ```bash
   docker exec ecommerce-postgres psql -U postgres -c "CREATE DATABASE ecommerce_test;"
   ```
2. Добавьте в корневой `.env`:
   ```env
   TEST_DATABASE_URL=postgresql://postgres:postgres@localhost:5432/ecommerce_test
   ```
3. `npm test` — раннер сам накатит миграции на тестовую БД и запустит все тесты.

## CI

В GitHub Actions (`.github/workflows/ci.yml`) тесты идут на сервисной PostgreSQL `allmaz_test` перед сборкой. Красные тесты → красный CI → ветка `production` не обновляется → на сервер ничего не уходит.

## Как писать новые тесты

- Рядом с кодом: `что-то.spec.ts` (без БД) или `что-то.int.spec.ts` (с БД). Файл с БД первой строкой импортирует `../../test/setup-env`, в `beforeEach` вызывает `resetDb`, данные создаёт через `test/db.ts` (`createUser`, `createProduct`, `addToCart`, `createPromo`, `createOrder`).
- Внешние сервисы (почта, ЮKassa) подставляются заглушками прямо в конструктор сервиса.
- Если логику можно проверить без БД — выносите её в чистую функцию (пример: `promo-codes/promo-discount.ts`): такие тесты быстрые и идут всегда.
